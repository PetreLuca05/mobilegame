- Measured by the reference reader: string table **1,843,386 bytes** (26,479 strings), longest string
  **1,776 bytes**, largest single script **`s-barrett_dx-praga-p1`** (12 steps, 25,117 bytes of strings it pulls in:

- Text lengths, measured in characters (Unicode code points): stem max **287**, option / answer / entry max
  **621**, explanation max **1,681**, teach text (one atom) max **1,636**. The longest string in the pack is
  1,776 bytes. **Explanations, stems and teach text scroll inside the card; no text is ever cut, shortened or
  ellipsised to fit.** Options wrap onto as many lines as they need.

## Pack binary layout (`gastro.mgpack`, version 3)

- Little-endian throughout; the file is read in place (embed it, point into it). Header at offset 0: `magic` u32 = "MGPK",
  `version` u32 = 3, `fact_count` u32, `item_count` u32, then 16 table descriptors `{offset u32, count u32,
  record_size u32}` (13 used, the rest zero) = 208 bytes. Every table starts 8-byte aligned.
- Strings: one table of NUL-terminated UTF-8; a string field is a u32 offset into it (0 = empty, `0xFFFFFFFF` = none). Index
  fields are u32 / u16 row numbers into the named table (`0xFFFF` / `0xFFFFFFFF` = none). `refs` is a shared u32 array:
  item → facts, teach step → atoms.

| # | table | record bytes | count | offset | holds |
|---:|---|---:|---:|---:|---|
| 0 | strings | 1 | 1,843,386 | 208 | NUL-terminated UTF-8, addressed by u32 offsets |
| 1 | rooms | 28 | 85 | 1,843,600 | map room id, name, storey, rectangle |
| 2 | topics | 40 | 50 | 1,845,984 | id, title, room, chapter, step; fact / item / script ranges |
| 3 | atoms | 20 | 657 | 1,847,984 | printed text unit: page, topic, kind, layer |
| 4 | facts | 20 | 3,349 | 1,861,128 | claim, atom, topic, page, type, flags (needs_review, unverified_ocr) |
| 5 | items | 40 | 3,478 | 1,928,112 | stem, explanation, review note, type, flags, option / fact-ref ranges, correct mask |
| 6 | opts | 20 | 10,301 | 2,067,232 | options, gaps, card answers, sort / match / order / label entries |
| 7 | refs | 4 | 9,152 | 2,273,256 | u32: item → facts, teach step → atoms |
| 8 | scripts | 36 | 382 | 2,309,864 | id, title, topic, room, kind, required, part / parts, prop / slot / npc, step range |
| 9 | steps | 12 | 3,870 | 2,323,616 | stage (predict / teach / check), flags, item or atom-ref range |
| 10 | props | 28 | 201 | 2,370,056 | iprop: id, kind, label, room, furniture row (on_model) or none, storey, yaw, x, z |
| 11 | slots | 28 | 33 | 2,375,688 | islot: id, kind, room, storey, yaw, x, z |
| 12 | figlabels | 20 | 177 | 2,376,616 | figure label text + box on the 200-dpi crop |
| 13 | furniture | 36 | 1,125 | 2,380,160 | every furniture piece and door leaf of institute.map: id, kind, room, storey, mount, yaw, x, z, w, d, h |

- Reference reader: `content/gastro/mgpack_read.c` (C11, ~200 lines, no allocation after load) checks the header, every
  table bound and record size, every string offset and cross-reference, and prints counts and sizes. `check.py` compiles it
  with `-Wall -Wextra -Werror -include gastro.mgpack.h` and runs it against the pack; the check fails if it rejects the pack
  or its counts differ from the sources. The engine loader is that file without the checks' printing.

## Rules that do not change

- Every fact is taught in its room; a room is complete when every fact of its topics has been answered correctly at least
  once (an item answered correctly sets the bits of its `fact_ids`; for multiplu only a fully correct answer counts). A
  chapter exam (Sala Comisiei) opens when every room of the chapter is complete. Review scripts (round, garda, exams) never
  count toward completion.
- Show the book as printed: items flagged `needs_review` (errata) or `unverified_ocr` (hidden text) show a small marker and
  their `review_note`; never rewrite pack text at run time.
- The repository is public: no text of the book may be committed (the pre-commit hook refuses 12-word runs). The pack and
  figures are never copied into `assets/`.

## Steps

### S0. Prerequisite: MAP-2 merged

The institute scene exists (step 1 of "Order of work") and loads `iprop` / `islot`; `assets/world/books.json` points Gastro's
`scene` at it. Check that every `iprop` id, room and storey of `institute.map` is reachable from game code by id.

### S1. Build: a private content location, compiled at build time

- Known before you start: on Linux the desktop build fails in `engine/audio/audio_sdl.c` (`M_PI` is undeclared under
  `-std=c11`; glibc defines it only with `_DEFAULT_SOURCE` / `_GNU_SOURCE`). BOOK-1 did not touch that file; fix it in the
  engine step.

- **Open question for the author (propose, do not decide):** where the pack lives. Proposal: a private repository (or
  private bucket) holding `gastro-pack.zip`, pinned in `content/CONTENT.lock` (path | sha256 | source, same format and
  checker as `assets/ASSETS.lock` / `tools/assets_lock.py`), fetched at configure time with a token from the environment.
- CMake: when `content/src/gastro-pack.zip` (or an unpacked `content/gastro/` with `atoms.jsonl`) is present and matches the
  lock, run `content/gastro/check.py` (must pass) and `tools/book/packbin.py` into `${MG_GEN_DIR}/content/gastro.mgpack` and add
  it and the figure atlas to `MG_EMBED_FILES`. When absent (public CI), embed a **stub pack** generated from the public
  files (ids, rooms, props, counts; placeholder strings) so the public build and tests stay green.
- No JSON parsing of the pack at run time; `packbin.py` is the only producer of the binary.

### S2. Loader: zero-copy, zero allocation per frame

- At build time the map loader runs the same equality check as `check.py`: every furniture `prop` record of `institute.map`
  against the pack's `furniture` table (same ids, same kinds, positions within 1 cm), and every `iprop` / `islot` with a
  furniture row against that row. A mismatch fails the build.

- `game/pack.c` / `pack.h`: `pack_open(const void *blob, size_t size)` checks magic, version and that every table fits
  (offset + count × size ≤ size, record sizes equal the `_Static_assert`ed struct sizes), then keeps typed pointers into
  the embedded blob. Strings are `blob + strings.offset + off`. Lookups by index; topic → contiguous fact / item / script
  ranges (the compiler sorts by topic). One `perm` arena allocation for the derived per-room tables; nothing in the frame.
- ctest `test_pack.c`: open the stub pack and a corrupted copy (bad magic, short table) — the second must be refused.

One instanced batch per mesh per visible storey. Kinds visible per storey (furniture + book kinds) and meshes once the
kinds of one family share a mesh (`mesh_groups` in `prop_kinds.json`):

| storey | visible kinds | meshes (shared) |
|---:|---:|---:|
| 0 | 69 | 43 |
| 1 | 64 | 40 |
| 2 | 61 | 40 |
| 3 | 60 | 34 |

- Draw only the view storey's furniture (storeys above are faded out; the ones below lie under an opaque slab; from
  outside, interiors are drawn only while the roof is not opaque, as today). Then furniture and book props add at most
  **43 instanced draws** on the busiest storey with shared meshes (69 without sharing), plus ≤ 3 UI draws
  while a card is open, against the **150-draw** frame budget: measure the current scene's draws first and keep the sum under
  150. Drawing every storey at once would cost 157 shared / 254 unshared: not allowed.
- More than 30 kinds are visible on every storey, so these families share a mesh (unit geometry scaled per instance, colour
  per instance): **seat** (chair, corridor_chair, auditorium_seat, alcove_seat); **bench_seat** (bench_seat, corridor_bench); **plant** (plant, corridor_plant, planter); **wall_panel** (wall_poster, notice_poster, pharmacy_sign, lift_sign, book poster, book plaque); **screen_panel** (wall_screen, info_screen, desk_screen, counter_screen); **table** (exam_desk, side_table, reading_desk, conference_table, desk_papers); **cabinet** (cabinet, tall_cabinet, cupboard, book cabinet); **shelf** (shelf, scope_cabinet, book shelf); **counter** (dispensing_counter, station_counter, reception_desk, nurse_counter, book counter); **lab_bench** (lab_bench, lab_island, book bench); **couch** (exam_couch, or_table, gurney); **cart** (supply_cart, anaesthesia_cart, instrument_table, book cart); **monitor** (monitor, book monitor); **tower** (trolley_tower, book scope_tower); **board** (whiteboard_stand, book board); **lightbox** (lightbox_stand, book lightbox); **curtain** (bed_curtain, privacy_screen); **model** (anatomy_model, book model); **podium** (podium, lectern, book podium); **iv** (iv_pole, book iv_stand); **sink** (sink, scrub_sink, wc_basin).
- Memory (estimate): 52 distinct meshes × ≤ 300 triangles ≈ 1.2 MB of vertex data; instance transforms

  rasterises 1,012 more colliders (measure the bake time with `--autotest nav`).

### S3. Props and slots

MAP-2 draws them (instanced per kind: one draw per kind per visible storey, at most 13 iprop kinds on one
storey). BOOK-ENGINE only needs the prop / slot index → world position and storey, from the pack's `props` / `slots` tables.

### S4. Interactions: reuse the registry and its 10 Hz scan

- Each **anchor** (a prop, an NPC point or a map slot that scripts use) becomes one interactable (`ia_add`, a new kind
  `IA_SCRIPT` with the anchor's script list), label = the next unfinished script's title (parts in order), `on_interact`
  opens the script player. Register only the anchors of the **current storey** (most on one storey: 88),
  re-registered on storey change; this keeps the registry under `IA_MAX` (320) with NPCs and markers. The scan, ranges
  (2.0 / 2.5 m) and the panel are unchanged.
- A room's station shows a marker until the room is complete (existing `markers.c`).

### S5. Script player and item widgets (UI-1 Jelly Pop)

- One modal card (scrim, no blur pass) that plays the steps in order: `predict` (an item before teaching; wrong answers are
  fine), `teach` (the atoms' text with the printed page; figures from the atlas), `check` (items). Widgets per item type:
  simplu (5 options, one tap), multiplu (5 toggles + confirm), cloze (a chip row of candidate tokens from the same item and
  its siblings; the gap fills), card (flip), sort (drag chips into 2–3 bins), match (two columns), order (drag to reorder),
  label (the figure with blank boxes from `figures.json`; drag labels). After an answer: the explanation (it quotes the
  book sentence and page) and, for multiplu, each false option's `why`.
- All widgets from `ui_widgets.c` / `k_ui` tokens; targets ≥ 44 pt; strings from the pack (Romanian), chrome from
  `assets/strings.json`. One UI batch: the card must not add more than 3 UI draws (UI-1 gate).

### S6. Progress: a bitset per account

- Local: `prefs.json` gains `book` {pack id, fact bitset base64, per-item last result}; written atomically on change
  (throttled to 1 s), on background and exit.
- Supabase: table `fact_progress (owner uuid references auth.users, pack text, bits bytea, updated_ms bigint)` with
  owner-only RLS and RPC `fact_progress_merge(p_pack, p_bits)` = bitwise OR with the stored bits (monotone: no conflict).
  **Merge coverage rule:** name `public.fact_progress` in `merge_ticket_redeem` with an explicit rule (OR the two accounts'
  bits); `supabase/tests/link_test.sql` must pass. Migration `<timestamp>_fact_progress.sql`.
- Pack versions: the bitset is keyed by fact index; ship `fact id → index` in the pack and remap a saved bitset by id when
  the pack id changes (facts removed → bits dropped, new facts → 0).
