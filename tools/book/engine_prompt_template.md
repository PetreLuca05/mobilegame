## Pack binary layout (`gastro.mgpack`, version {VERSION})

- Little-endian throughout; the file is read in place (embed it, point into it). Header at offset 0: `magic` u32 = "MGPK",
  `version` u32 = {VERSION}, `fact_count` u32, `item_count` u32, then 16 table descriptors `{offset u32, count u32,
  record_size u32}` (13 used, the rest zero) = 208 bytes. Every table starts 8-byte aligned.
- Strings: one table of NUL-terminated UTF-8; a string field is a u32 offset into it (0 = empty, `0xFFFFFFFF` = none). Index
  fields are u32 / u16 row numbers into the named table (`0xFFFF` / `0xFFFFFFFF` = none). `refs` is a shared u32 array:
  item → facts, teach step → atoms.

| # | table | record bytes | count | offset | holds |
|---:|---|---:|---:|---:|---|
{LAYOUT_TABLE}

- Reference reader: `content/gastro/mgpack_read.c` (C11, ~200 lines, no allocation after load) checks the header, every
  table bound and record size, every string offset and cross-reference, and prints counts and sizes. `check.py` compiles it
  with `-Wall -Wextra -Werror -include gastro.mgpack.h` and runs it against the pack; the check fails if it rejects the pack
  or its counts differ from the sources. The engine loader is that file without the checks' printing.

## Rules that do not change

- Every fact is taught in its room; a room is complete when every fact of its topics has been answered correctly at least
  once (an item answered correctly sets the bits of its `fact_ids`; for multiplu only a fully correct answer counts). A
  chapter exam (Sala Comisiei) opens when every room of the chapter is complete. Review scripts (round, garda, exams) never
  count toward completion.
- Show the book as printed: items flagged `needs_review` (errata) or `unverified_ocr` (hidden text) show a small marker and
  their `review_note`; never rewrite pack text at run time.
- The repository is public: no text of the book may be committed (the pre-commit hook refuses 12-word runs). The pack and
  figures are never copied into `assets/`.

### S1. Build: a private content location, compiled at build time

- Known before you start: on Linux the desktop build fails in `engine/audio/audio_sdl.c` (`M_PI` is undeclared under
  `-std=c11`; glibc defines it only with `_DEFAULT_SOURCE` / `_GNU_SOURCE`). BOOK-1 did not touch that file; fix it in the
  engine step.

- **The repository is public: the real pack never enters it.** The real `gastro.mgpack` (v4), its header and the figure
  crops live in a git-ignored folder on the build machine, **`content_private/gastro/`** (in `.gitignore`; the leak guard
  refuses any staged or tracked path under it, and `check.py --leak` fails on one). The engine bundle the author hands over
  (`BOOK-1_engine_bundle.zip`) unpacks there.
- CMake: when `content_private/gastro/gastro.mgpack` is present, embed it and its figure crops (`MG_EMBED_FILES`, under the
  name `content/gastro.mgpack`). When it is absent, embed the **dummy pack** committed at `content/gastro_demo/gastro.mgpack`
  (2 arcs, 3 cases, 6 rooms of invented filler, every item type, dialogue, people; same v4 format, regenerated with
  `python3 -I tools/book/make_dummy_pack.py content/gastro_demo`, accepted by `content/gastro/mgpack_read.c`), so the
  public repository and CI always build and run every test. A compile definition (`MG_CONTENT_DEMO=1`) marks the dummy
  build, and the game shows a small **„conținut demo”** tag (Jelly Pop chip, top left, under the account chip) whenever it
  runs on the dummy pack.
- A shipped build (`tools/archive_ios.sh`, `tools/build_aab.sh`, any Release archive) **fails at configure time** if the
  real pack is missing: never ship the demo.
- No JSON parsing of the pack at run time; `packbin.py` is the only producer of the binary; the loader runs the same
  checks as `mgpack_read.c` (header, record sizes, indices, strings) on whichever pack is embedded.

### S2. Loader: zero-copy, zero allocation per frame

- At build time the map loader runs the same equality check as `check.py`: every furniture `prop` record of `institute.map`
  against the pack's `furniture` table (same ids, same kinds, positions within 1 cm), and every `iprop` / `islot` with a
  furniture row against that row. A mismatch fails the build.

- `game/pack.c` / `pack.h`: `pack_open(const void *blob, size_t size)` checks magic, version and that every table fits
  (offset + count × size ≤ size, record sizes equal the `_Static_assert`ed struct sizes), then keeps typed pointers into
  the embedded blob. Strings are `blob + strings.offset + off`. Lookups by index; topic → contiguous fact / item / script
  ranges (the compiler sorts by topic). One `perm` arena allocation for the derived per-room tables; nothing in the frame.
- ctest `test_pack.c`: open the stub pack and a corrupted copy (bad magic, short table) — the second must be refused.

### S4. Missions: the book is reached only through NPCs (pack v4 tables)

The author's rule: **per mission, never per room**. No room card or prop lists the scripts; every required script is one
step of a case and is played by talking to an NPC. `tools/book/missions.py` builds `missions.json` from the authored
`missions_src.json`; `packbin.py` writes it into `gastro.mgpack` **v4** (the v3 header had 16 table slots, 14 used; v4 has
32): `cast` (36 B), `arcs` (16 B), `missions` (32 B), `quests` (20 B), `msteps` (60 B), `lines` (8 B: text, speaker, role),
`people` (44 B), all fixed-size records with string offsets; `mgpack_read.c` checks every index, that each required script
is in exactly one step and that each presenter stands inside its room. Dialogue: {DLG_LINES} lines, {DLG_BYTES} bytes, the
longest {DLG_LONGEST} bytes (text scrolls, never cut).

- **Shape:** 5 arcs (the clinic chief opens and closes each) > 17 cases (giver, patient, ward, intro / outro, a one-line
  summary) > 50 quests (one topic, its host) > 382 steps (script, presenter, stand point, the object it is about, the
  patient's bed / seat and pose, the opening line and two replies).
- **Progress stays per fact.** A step is done when every fact its script covers is set in the account's fact bitset
  ({BITSET} bytes); a quest, a case and an arc are done when all their steps are. The only extra state is one
  accepted + closed bit pair per case: **{CASE_BYTES} bytes** per account, next to the fact bitset.
- **Gates (all of them):** a case closes (its giver's debrief) only when its steps are done; a chapter exam opens only
  when its rooms are complete (`scripts.json` pools). Nothing else: any case can be accepted at any time from its giver or
  the journal, any step of an accepted case can be played in any order (the marker suggests the book order), and no arc
  or case waits for another.
- **Flow:** the tracked case's giver carries the objective marker → talk → intro + case → accept → the marker moves to the
  next undone step's presenter → talk → (quest intro on its first step) + the step's line → start → the script player (S5)
  with the presenter's name in its header → the presenter's reply (+ the quest's done line) → next. All steps done → back
  to the giver → outro (+ the arc outro after its last case) → reward (T3).
- **Staging:** the presenter of the objective step walks (same storey, in view) or is placed at its stand point; a case
  step's patient lies or sits at the step's bed / seat. A case step happens only with the patient present.
- **Logic and reach (checked at build time, no run-time snapping):** nothing outdoors; patients only in clinical rooms;
  treatment chosen only in a pharmacy, ward, bay, consult room or OR; every presenter stands within the **2.0 m** talking
  range of a cell the player can reach on the map's walk grid (`tools/book/model_nav.js`: the page's geometry, everything
  drawn solid, 0.25 m cells, capsule 0.3 m, the same rules as `navgrid.c`). A presenter behind a counter is spoken to
  across it. The map check also requires a free 1.0 m approach on both sides of every door and every room's floor
  reachable from the entrance (stairwells exempt: the stair flight fills them and collides as one box).
- **Doors and the grid:** every door opening must hold at least **2 walkable cells across its width** (checked: {DOOR_MIN}
  to {DOOR_MAX} on the {DOORS_CHECKED} doors that are not stairwells). With 0.25 m cells and the 0.3 m capsule inflation the
  grid supports doors of **1.2 m** (1.1 m leaf) or wider, as in `navgrid.c`; 0.9–1.0 m doors give 0–1 cells and the room
  behind is unreachable (the institute's toilets were widened from 0.9 m to 1.2 m for this). Two cells are guaranteed at any
  offset to the grid from a 1.25 m clear opening; MAP-2 keeps door centres on the model's 0.05 m grid, where 1.2 m gives
  exactly 2.
- **Reused, unchanged:** the objective marker is `markers.c` (one marker, the chapter colour, edge icon, distance, floor
  badge, tap = autonav); talking is the proximity interaction of `interact.h` (10 Hz scan, 2.0 / 2.5 m, the bottom-right
  panel with the NPC's floating head, `IA_PRIORITY` for the objective's presenter, others greet for 2.5 s and nod); the
  journal is a page of the existing pause card; autonav and lifts as today.
- **New:** the objective pill (top left: case, who, room, storey, steps done); the dialogue card (portrait, name, role,
  lines with Continue, two choices); the journal page (arc tabs, case cards with stages, Track / Take me there); the case
  state bits; staging the presenter and patient; loading the people table.

### S6. Progress: a bitset per account
